# Журнал посещений с фильтром по URL-пути

Мини-сайт на Next.js для деплоя на Vercel. Он показывает журнал посещений и записывает каждый просмотр любого URL-пути, кроме корня сайта `/`.

## Поведение

- Открытие `/` показывает журнал, но не создаёт запись.
- Открытие `/about`, `/contacts`, `/catalog/item-1` и любого другого непустого пути создаёт запись.
- Перезагрузка непустого пути создаёт ещё одну запись.
- Переход на другой путь внутри приложения также регистрируется.
- В таблице сохраняются путь (`path`) и серверное время (`created_at`).
- Фильтр содержит все уникальные пути из всей базы, а не только из последних 500 строк.
- В таблице показываются последние 500 посещений с учётом фильтра; счётчик показывает полное количество записей по выбранному фильтру или по всем путям.
- Query-параметры (`?q=...`) не сохраняются: фиксируется pathname, например `/catalog/item-1`.
- IP-адреса, User-Agent, cookies, имена и идентификаторы устройств приложением не сохраняются.

## 1. Настроить Supabase

1. Создайте проект на https://supabase.com/.
2. Откройте **SQL Editor → New query**.
3. Выполните весь файл `schema.sql`. Скрипт создаёт таблицу/функцию и подходит для миграции с предыдущей версии: старые записи получат путь `/` и не будут отображаться как посещения страниц.
4. В **Project Settings → API** скопируйте Project URL и `service_role` key.
5. Не публикуйте `service_role` key и не помещайте его во frontend.

## 2. Развернуть на Vercel

1. Загрузите содержимое проекта в GitHub.
2. Импортируйте репозиторий на https://vercel.com/.
3. В **Project → Settings → Environment Variables** добавьте:
   - `SUPABASE_URL` — Project URL из Supabase;
   - `SUPABASE_SERVICE_ROLE_KEY` — секретный service role key.
4. Выполните Redeploy.

## Локальный запуск

```bash
npm install
```

Создайте `.env.local` с переменными из `.env.example`, затем:

```bash
npm run dev
```

Откройте `http://localhost:3000`.

## Важные ограничения

- Это журнал просмотров URL, а не уникальных посетителей: 10 перезагрузок одного пути = 10 записей.
- Любой посетитель может открыть журнал. Для приватного доступа нужна авторизация.
- Публичный endpoint можно спамить запросами. Для публичного production-сайта добавьте rate limiting/защиту от ботов.
- Приложение отображает журнал на любом URL-пути, поскольку используется catch-all route. Поэтому URL `/about` здесь служит и примером посещённого пути, и адресом, при открытии которого журнал запишет `/about`.
